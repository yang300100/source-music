# 源音乐鸿蒙版 — 设计文档

> 日期：2026-08-06 | 状态：已确认 | 目标：开发一个可导入音源的音乐播放软件，充分利用鸿蒙系统特性

---

## 一、项目概述

基于开源项目 [参考移动端项目](参考移动端项目) 的「壳与音源分离」架构理念，为 HarmonyOS 开发一个原生音乐播放器。

**核心差异化**：播放器本身不含任何内置音乐源或版权内容。所有音乐数据来自用户自行导入的 JS 脚本（兼容原版生态）或 ArkTS 原生音源模块。类似于 BT 客户端，应用只是工具，数据源由用户决定。

## 二、推进策略：三阶段路线图

### 🚀 第一阶段：MVP（核心链路跑通）

**目标**：可安装的 .hap 包，能用社区 JS 音源搜歌、播放、看歌词

| 功能 | 说明 |
|------|------|
| 音源导入 | 本地 .js 文件导入 + 在线链接导入，QuickJS 沙箱执行 |
| 多音源搜索 | 并发请求所有启用的音源，去重合并，按优先级排序 |
| 音乐播放 | 基于 AVPlayer，支持网络流媒体、后台播放 |
| 歌单管理 | 创建/编辑/删除歌单，添加/移除歌曲 |
| 歌词显示 | LRC 逐行滚动，原文+译文对照，点击跳转 |

### 🧩 第二阶段：功能补齐（原版全覆盖）

**目标**：功能对标原版 参考移动端项目，覆盖全部日常使用场景

- 本地音乐扫描与播放（MP3/FLAC/WAV/OGG）
- 深色/浅色主题切换
- 歌单导入/导出（.json 格式）
- 均衡器 & 音效
- 播放模式（单曲循环/列表循环/随机/顺序）
- 通知栏播放控制
- 自动换源（当前源失效时尝试其他源）
- 备份恢复

### ✨ 第三阶段：鸿蒙深度集成

**目标**：真正的「鸿蒙原住民」音乐播放器

- 分布式流转（手机播一半，流转到平板/智慧屏继续播）
- 元服务卡片（桌面快捷播放控制）
- 多端响应式布局（手机 → SideBar 收起，平板 → SideBar 展开）
- 耳机/手表协同控制
- 无缝接续（换设备自动恢复播放进度）
- 语音唤醒

## 三、架构设计

### 3.1 模块划分（HSP 特性模块架构）

```
entry/                  # 主模块（壳）- 导航框架、路由、全局状态
hsp-player/             # 播放器模块 - AVPlayer 封装、播放队列、状态机
hsp-source/             # 音源引擎 - 音源接口 + QuickJS 沙箱 + 多音源管理
hsp-search/             # 搜索模块 - 聚合搜索、去重合并、搜索历史
hsp-playlist/           # 歌单模块 - CRUD、导入导出、收藏管理
common/                 # 公共基础 - 网络、存储、日志、工具
```

**关键原则**：
- 壳与音源分离：entry 不含任何内置音源
- 模块独立编译：修改播放器不碰音源模块
- 按需打包：不同设备形态选择性包含不同 HSP
- 渐进扩展：第三阶段加 hsp-distribute / hsp-metaservice，不动已有模块

### 3.2 导航结构

- **MVP 阶段**：SideBar 侧边栏导航
  - 正在播放 | 搜索 | 我的歌单 | 本地音乐 | 音源管理 | 设置
- **第三阶段**：响应式适配
  - 手机（<600vp）→ 底部 Tab
  - 平板/2in1（≥600vp）→ SideBar 展开

### 3.3 状态管理（ArkUI 原生方案）

| 状态类型 | 方案 | 数据示例 | 生命周期 |
|----------|------|----------|----------|
| 组件内状态 | @State / @Link | 搜索框文本、开关状态 | 跟随组件 |
| 页面间共享 | @Provide / @Consume | 搜索结果、歌词数据 | 导航栈 |
| 全局持久 | AppStorage / PersistentStorage | 播放队列、音源列表、设置 | App 生命周期 |
| 播放器状态 | @Observed + @ObjectLink | 播放状态、当前歌曲、进度 | 跨页面全局 |

## 四、核心模块设计

### 4.1 音源引擎（hsp-source）

**双轨并行机制**：

- **JS 兼容模式**（MVP 优先）：编译 QuickJS 为鸿蒙原生库，在沙箱中执行 .js 音源脚本。兼容原版 社区音源 社区生态。
- **ArkTS 原生模式**（后续）：定义 ArkTS 音源接口，开发者用 TypeScript 写原生音源模块。

**音源接口规范**：

```typescript
interface MusicSource {
  getSourceInfo(): SourceInfo           // 名称、版本、作者
  search(query: string, page: number): SearchResult  // 搜索
  getMusicInfo(songmid: string): MusicInfo           // 获取播放URL
  getLyric(songmid: string): LyricData               // 获取歌词
  getPlaylistInfo(listid: string): PlaylistInfo      // 获取歌单
  getHotSearch(): HotSearchItem[]                    // 热搜推荐
}
```

**安全沙箱限制**：
- 仅可调用音源接口定义的 API
- 网络请求限速，仅白名单域名
- 无文件系统访问（除自身配置）
- 无法调用系统 API 或获取设备信息
- 超时 30 秒自动终止
- 沙箱崩溃不影响主 App

**多音源管理**：
- 每个音源独立开关
- 拖拽排序优先级
- 搜索时并发请求所有启用的源
- URL 失效时自动按优先级切换

### 4.2 播放引擎（hsp-player）

**技术选型**：鸿蒙 AVPlayer

| 能力 | AVPlayer 支持情况 |
|------|-------------------|
| 网络流媒体 | ✅ 传入 URL 直接播放 |
| 格式支持 | ✅ MP3/FLAC/AAC/OGG/WAV |
| 后台播放 | ✅ 系统级后台 + 通知栏控制 |
| 开发复杂度 | ✅ 极低，几行代码出声音 |
| 均衡器/音效 | ⚠️ 有限支持（后续可选 AudioRenderer 补充） |

**播放器状态机**：

```
空闲 → 获取URL → 缓冲中 → 播放中 ⇄ 暂停
                      ↓
                  URL失效 → 换源重试 → 获取URL
```

**播放队列**：
- 支持三种来源：搜索结果临时队列 / 歌单队列 / 本地文件队列
- 播放模式：顺序 / 单曲循环 / 列表循环 / 随机
- 自动切歌（当前播完 → 下一首）

### 4.3 搜索系统（hsp-search）

**聚合搜索流程**：
1. 用户输入关键词
2. 并发请求所有启用音源（最多 5 个并发）
3. 统一标准化格式
4. 按（歌名 + 歌手）去重
5. 合并同一首歌的不同音源（用户可切换）
6. 按音源优先级排序展示

**附加功能**：搜索历史（本地 50 条）、热搜推荐、链接直达歌单

### 4.4 歌单管理（hsp-playlist）

- 创建/编辑/删除歌单
- 从搜索结果添加歌曲到歌单
- 导入/导出 .json 格式（兼容原版）
- 收藏管理

### 4.5 歌词系统

- 从音源获取 LRC 格式歌词
- 解析时间标签，逐行滚动
- 当前行高亮 + 颜色过渡
- 原文 + 译文对照显示
- 点击某行跳转到对应时间
- 兜底策略：无歌词显示「纯音乐」、无时间标签按段落展示
