搜索、歌词与状态管理 — MVP 收官设计

三个核心能力合在一页，快速过完

🔍 多音源聚合搜索

用户输入关键词 → 同时发给所有启用的音源（最多 5 个并发）→ 等所有结果回来 → 去重合并（同歌名+同歌手=同一首）→ 按音源优先级排序展示

每个搜索结果标记来源（比如「🐶 酷狗」「☁️ 网易」），用户可以切换音源获取不同音质，或者让 App 按优先级自动选。

搜索流程

1️⃣ 输入关键词

2️⃣ 并发请求 5 个音源

3️⃣ 收集结果，统一格式

4️⃣ 按歌名+歌手去重

5️⃣ 合并同一首歌的不同音源

6️⃣ 按优先级排序展示

搜索历史 & 热搜

🕐 本地搜索历史（最多50条）

🔥 热搜推荐（从音源获取）

🗑 一键清除历史

🔗 支持粘贴链接直达歌单

🎤 歌词显示

播放器拿到歌曲 ID → 调用音源 getLyric() → 返回 LRC 格式歌词 → 解析时间标签 → 根据播放进度逐行高亮滚动

支持 原文 + 译文对照（上下两行，原文白色译文灰色），支持 手动滚动查看，点击某一行跳转到对应时间。

歌词能力

✅ LRC 逐行滚动

✅ 当前行高亮 + 颜色过渡

✅ 译文对照（双语歌词）

✅ 点击跳转播放位置

✅ 手动拖动预览

兜底策略

⚠️ 无歌词 → 显示「纯音乐，请欣赏」

⚠️ 无时间标签 → 按段落展示

⚠️ 音源获取失败 → 换源重试

⚠️ 网络超时 → 提示用户手动切换

🗄 状态管理（ArkUI 原生方案）

状态类型 用什么管 放什么数据 生命周期
组件内状态 @State / @Link 搜索框文本、开关状态、弹窗显隐 跟随组件
页面间共享 @Provide / @Consume 当前歌单、搜索结果、歌词数据 跟随页面导航栈
全局持久状态 AppStorage / PersistentStorage 播放队列、音源列表、主题偏好、设置 App 整个生命周期
播放器状态 @Observed + @ObjectLink 播放状态、当前歌曲、进度、播放模式 跨页面全局

全原生方案的优势

  • 零第三方依赖，包体积更小
  • 与 ArkUI 渲染管线深度集成，更新高效
  • 类型安全，ArkTS 编译期检查
  • PersistentStorage 自动落盘，无需手写序列化

注意点

  • 深层组件树 @Provide/Consume 链需规划好
  • 复杂全局状态建议收敛到一个 AppState 类
  • PersistentStorage 仅支持简单类型
